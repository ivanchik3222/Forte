# Проверка обучающего датасета

Проверена папка `ML/open/open`. Исходные видео и Excel не изменены. Все данные обрабатывались локально.

## Состав и техническая проверка

- 42 MOV-файла и 42 строки разметки на листе `labels`, диапазон A2:C43.
- 22 строки с нарушением, 20 без нарушения. Все файлы сопоставлены со строками.
- Все 22 положительные строки имеют таймкод. Все таймкоды находятся внутри соответствующего ролика.
- Все файлы полностью декодированы PyAV без ошибок; число декодированных кадров совпадает с числом кадров, сообщённым OpenCV.
- Кодек H.264, разрешение 464×848, аудиопотоков нет.
- Длительность 11.633–142.533 секунды; суммарно 1444.164 секунды (24 минуты 4 секунды, включая копии).
- Средний FPS по метаданным OpenCV: примерно 29.76–30.00. Для точных таймкодов следует использовать PTS кадров.
- Общий размер файлов 292870994 байта, примерно 279.3 MiB.

## Дубликаты

SHA-256 выявил две пары побайтово одинаковых файлов:

| Файлы | Метки | Таймкоды |
| --- | --- | --- |
| Х-4.mov / Х-47.mov | оба с нарушением | 57 / 68 секунд |
| Х-5.mov / Х-48.mov | оба без нарушения | отсутствуют |

Итого 40 уникальных видео: 21 положительное и 19 отрицательных. Разные таймкоды в одной копии не доказывают ошибку разметки: в одном ролике могут быть два события. При подготовке данных сохранить обе временные отметки для ручной проверки. Копии всегда помещать в одну группу при разбиении данных.

## Разметка

Доступны только имя файла, текстовый таймкод и бинарная метка. Типов событий, описаний действий, временных интервалов, боксов и нормативных ссылок нет. В именах смешаны латинская X и кириллическая Х; текущие строки совпадают с файлами. Загрузчик должен нормализовать идентификатор, сохраняя исходный путь. Строка `1минута 8 секунда` для Х-47 означает 68 секунд.

## Визуальная проверка

Просмотрены три выбранных кадра из каждого ролика и пять кадров вокруг каждой положительной временной отметки (смещения −4, −2, 0, +2, +4 секунды с ограничением длительностью ролика). Это выборочный просмотр последовательностей, а не непрерывный просмотр всех видео.

Сцена повторяется: кассовая зона, стол, дверь, шкаф/место хранения, кассир и другие участники. Руки и небольшие предметы занимают мало пикселей. Видны изменения освещения. В положительных фрагментах встречаются уход/возвращение кассира, действия с дверцей шкафа, передача предметов, размещение сумки на столе и действия руками около рта. Это наблюдения и кандидаты для дополнительной разметки, а не подтверждённые типы нарушений или юридические выводы.

## Выводы для ML

1. Доразметить уникальные видео: наблюдаемое действие, тип события, начало/конец, кадры-доказательства, подтверждённое правило. Не считать все кадры положительного ролика нарушением, а неотмеченные фрагменты автоматически корректными.
2. Анализировать общий план вместе с обрезкой рабочей зоны в исходном разрешении. Не фиксировать зоны навсегда в координатах одной камеры.
3. Обучение и проверку разделять по группам копий и похожих сценариев. Проверять перенос между видимыми условиями съёмки, сохраняя отдельные ракурсы для проверки при появлении новых записей.
4. Положительные ролики в среднем короче отрицательных: 28.05 против 41.35 секунды. Проверить, что классификатор не использует длительность или фон как замену действию.
5. Использовать предобученную модель с небольшим обучаемым компонентом или локальную VLM с временной проверкой правил. Этот объём данных не обосновывает обучение большой видеомодели с нуля.
6. Собственные парные съёмки корректного и некорректного действия с разными углами полезнее, чем массовое добавление нерелевантных видео.

Технические результаты: `video_inventory.json`, `decode_checks.json`. Исходная разметка извлечена в `labels_raw.json`. Контактные листы и скрипты находятся в этой папке.

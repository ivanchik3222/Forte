# API без регистрации

Публичная страница фронтенда: `/api-access`, ссылка «API» в навигации главной страницы.
Базовый URL сервера берётся из `REACT_APP_API_URL`, включая существующий префикс `/forte`, если он используется.

## Ключи

- `POST /api/v1/api-keys` без регистрации → 201 `{api_key,expires_at}`. Ключ виден только в этом ответе, действует 30 дней. Браузер держит его только в памяти страницы, без localStorage.
- `DELETE /api/v1/api-keys/current` с `X-API-Key` → 204, немедленный отзыв доступа к задачам. Отзыв не удаляет файлы и не отменяет уже выполняющийся анализ.
- В БД хранится SHA-256 криптографически случайного 256-битного ключа, не сам секрет. Новый ключ создаёт нового независимого API-клиента; восстановления старых задач по новому ключу нет.
- Не передавайте ключ в URL, репозиторий или общедоступный JavaScript. Не включайте заголовок X-API-Key в access-логи прокси.

`POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` также принимают отдельный
секрет жюри из `JURY_API_KEY` или `JURY_API_KEY_FILE`. Ключ, выданный через
`/api-keys`, открывает изолированный API-клиент; секрет жюри запускает контракт
раздела 10 ТЗ с локальной reviewed pipeline. Ключи нельзя взаимозаменять.

## Анализ

```bash
curl -X POST "$BASE/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@video.mov"
curl "$BASE/api/v1/jobs/$JOB_ID" -H "X-API-Key: $KEY"
```

POST возвращает 202 `{job_id,status:"processing"}`. Принимается один `file`, MOV (а также MP4/WebM), проверяемый ffprobe, максимум 1 ГиБ. Idempotency-Key не требуется; повтор POST создаёт новую задачу, если предыдущая уже завершилась. Автоматически повторять POST после сетевой ошибки не следует: сохранение могло завершиться.

GET опрашивается раз в 3–5 секунд. Внутренний queued преобразуется в processing. Готовый ответ соответствует разделу 10 ТЗ: `{job_id,status:"done",verdict,violations}`; каждый элемент violations содержит type, timecode_sec, description и 1–3 evidence_frames с timestamp_sec и image_base64 (JPEG, без data-URI).

Если выбранный движок возвращает только наблюдения `requires_review`, API отвечает
`failed/verdict_unavailable`; такие результаты не превращаются в `no_violation`.
Reviewed pipeline доступна через секрет жюри на Apple Silicon. Её текущая оценка
проведена на development-выборке и не подтверждает точность независимого теста;
неклассифицированные эпизоды и кадры требуют проверки специалистом. Подробности
и ограничения: [интеграция ML](ML_INTEGRATION.md) и [аудит кейса](../ML/CASE_QA_AUDIT.md).

Будущий классификатор должен сохранять `result.verdict=violation|no_violation` и `result.violations`. Кадры каждого нарушения: `{timestamp_sec,image_file}`, где image_file — имя JPEG внутри `MEDIA_ROOT/analysis/{job_id}`. Сериализатор проверяет согласованность вердикта, поля событий, количество кадров, таймкоды и границы пути, затем читает JPEG и выдаёт base64.

Дедлайн — 300 секунд от создания задачи, включая очередь. Результат позже дедлайна выдаётся как failed/analysis_timeout. Просроченные задачи в очереди закрываются при следующей отправке или проходе worker. Дедлайн ответа не является принудительным завершением зависшего декодера; производительность и выполнение за 5 минут нужно отдельно проверить на сервере. Обычный JWT-анализ сохраняет прежний контракт наблюдений.

## Изоляция и ограничения

Видео принадлежит либо users.id (поле media_records.owner_id), либо api_clients.id (поле api_client_id); CHECK запрещает одновременно двух владельцев и отсутствие владельца. API-клиент не является пользователем. Его видео исключены из пользовательских списков и доступа через JWT, включая admin. API-ключ не открывает камеры, личный кабинет и подписанные пользовательские ссылки. Для неизвестной или чужой задачи возвращается 404. Просроченный/отозванный ключ → 401. Одновременные Authorization и X-API-Key при анализе, чтении задачи и отзыве → 400.

Ограничения по умолчанию:

- 3 выдачи ключа на IP и 100 глобально за окно 5 минут;
- 10 попыток загрузки на IP за окно 5 минут;
- 30 загрузок на API-клиента в час, одна активная задача;
- общая очередь с JWT-клиентами — 20 задач; проверка ёмкости и загрузка сериализованы общей блокировкой;
- проверка свободного места и размера файла как для пользовательских загрузок.

Счётчики в БД общие для процессов API. Используется request.remote_addr; непроверенный X-Forwarded-For не учитывается. За reverse proxy клиенты могут делить лимит адреса прокси. Перед публичным запуском настройте доверенную передачу клиентского IP на существующем шлюзе и согласуйте лимиты. Фиксированные окна допускают всплеск на границе окна. Истечение ключа не удаляет сохранённые файлы; автоматическая политика хранения ещё не введена.

## Обновление и проверка

Перед обновлением сделайте резервную копию БД. Из backend выполните `python -m flask --app app db upgrade`, затем перезапустите API и worker, пересоберите фронтенд. Миграция 0006 сохраняет пользовательские загрузки и добавляет альтернативного владельца. На SQLite перестройка таблицы требует остановки записи на время миграции. Downgrade запрещён при наличии API-загрузок, чтобы не потерять их молча.

Проверки: `python -m pytest backend/tests -q` из корня; `npm test -- --watchAll=false --runInBand` и `npm run build` из frontend. Тесты внешнего контракта используют подменённую модель и отдельно проверяют, что наблюдения реального формата не становятся отрицательным вердиктом.

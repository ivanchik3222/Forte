# MERL, EPIC-KITCHENS и MECCANO: исследовательская интеграция

17 октября 2026 года скачаны ограниченные выборки и выполнены локальные GPU-пилоты.
Исходный пяти-классовый детектор `models/cash_detector/best.pt` сохранён.
Ни один из этих источников не дал подходящую разметку банкнот для непосредственного
дообучения нашего `cash`. Объекты кухни/конструктора не переименовывались в деньги.

## Что использовано

| Источник | Локальная выборка | Использование |
| --- | --- | --- |
| [MERL Shopping](https://merl.com/research/downloads/MERL_Shopping_Dataset) | 10 видео, 167 321 374 байта; 526 интервалов | Обучение временного представления действий |
| [MECCANO](https://iplab.dmi.unict.it/legacy/MECCANO/) | 104 кадра, 190 боксов кистей; 6034 train/val-интервала действий | Предобучение и совместное обучение детектора кистей; словарь действий |
| [EPIC-KITCHENS-100](https://epic-kitchens.github.io/2026) | 67 217 train + 9668 val-интервалов | Словарь примитивов и статистика переходов по train |

Кадры MECCANO извлечены по HTTP Range из официального ZIP размером 34.7 ГБ;
архив целиком не скачивался. CRC ZIP и SHA-256 выбранных файлов сохранены.
У двух скачанных исходных боксов нижняя граница выходила за изображение на один
пиксель — координаты обрезаны по границе с сохранением исходных координат.
Просмотрена контактная таблица восьми примеров, а не проведена экспертная приёмка
всех исходных аннотаций. Кадры имеют размер 1920×1080, совпадающий с системой боксов.

У [EPIC-VISOR](https://epic-kitchens.github.io/VISOR/site) есть ручные маски рук,
активных предметов и контактные отношения. Официальный сервер data.bris разорвал
соединение при обычной проверке и при повторе вне sandbox. Поэтому **RGB и маски
EPIC не участвовали в обучении**. Они не заменены псевдоразметкой с других сайтов.
В загруженных train/val-таблицах не найдены money/cash/banknote/wallet/coin в noun
или narration. Это проверка выбранных таблиц, а не утверждение обо всех кадрах EPIC.

EPIC используется на уровне разметки последовательностей: `take`, `place`, `open`,
`close`, `inspect`, `manipulate`, `other`. Из train получены 46 074 соседних перехода
EPIC и 3306 MECCANO с разрывом не более 8 секунд. Пересекающиеся соседние интервалы
пропущены: их нельзя превращать в строгий порядок. Вероятности сглажены +1 по строкам.
Это статистический prior, **не визуальный классификатор и не доказательство банковского
действия**; он пока не применяется автоматически к банковским кадрам.

## Временная модель MERL

Обучение: субъекты 1–4, 6 видео. Val: субъекты 21–22, 4 видео. Сессии одного
участника остаются в одном split; test MERL не оценивался. Небольшой пилот выбран
до обучения по доступности загрузки, не по качеству модели.

Энкодер — локальный ImageNet ResNet18, заморожен; изображения RGB, признаки 512,
выборка 2 FPS по PyAV PTS. Среднее/стандартное отклонение рассчитаны только по train.
Временная модель использует признаки и их разности, три Conv1d со слоями dilations
1/2/4, ширину 64, dropout 0.2, пять независимых выходов. Контекст около семи секунд,
включая будущие кадры: обработка офлайн. Перекрывающиеся действия учитываются как
multi-label, а не принудительно как один класс. AdamW, 30 эпох, seed 42; best по val.

Важная проверка времени: `tlabs` относится к кадрам **исходного видео, 30 FPS в
скачанной выборке**. Упоминание 15 FPS в README описывает результаты авторов.
Для преобразования использован фактический FPS каждого исходного видео и проверено,
что максимальные номера разметки не выходят за число кадров. Границы трактуются
как 1-based inclusive; ошибка одного кадра меньше шага выборки 0.5 секунды.

| Модель / проверка | Macro frame AP на MERL val |
| --- | ---: |
| Модель отдельных кадров без временного контекста | 0.337 |
| Временная модель, исходный порядок | **0.464** |
| Те же временные веса, кадры перемешаны, предсказания восстановлены в исходный порядок | 0.192 |
| Те же веса, порядок кадров обращён | 0.327 |

Числа 0.337 и 0.464 — лучшие val за эпохи. Проверка порядка использует именно
сохранённые лучшие временные веса. Размеры моделей различаются; это исследовательское
сравнение с одним seed, а не изоляция единственного фактора архитектуры. При этом
проверка перемешивания сохраняет и веса, и набор кадров, показывая зависимость
предсказаний от временного контекста. Frame AP не равен event AP, object mAP или
точности нарушений на ForteBank.

Веса: `models/interaction_research/merl_temporal/temporal_best.pt`, `frame_best.pt`.
Истории и метрики: `runs/merl_temporal_research_v1/`. Сохранены state_dict,
нормализация, классы, seed, FPS, хеши весов, аннотаций и списка исходных видео.

## Детектор кистей и перенос MECCANO

Одноклассовые датасеты: `native_hands_research_v1`, `meccano_hands_research_v1`.
Native/Roboflow train — 165 изображений, включая ранее подготовленные аугментации;
val — исходные 10 кадров ForteBank, 20 кистей. MECCANO train — 88 кадров из 11 видео,
val — 16 кадров из двух других видео. Test не использовался.

Все финальные сравнения кистей используют YOLO11n, вход 640, batch 5, AdamW,
lr=0.0003, freeze=0, seed 42, одинаковый native val. Порог conf=0.25, NMS IoU=0.3;
IoU сопоставления с истинной разметкой ≥0.5. Метрики здесь только для `hand`;
их нельзя сравнивать с общим mAP пяти классов исходного детектора.

Первый вариант: 20 эпох MECCANO, затем 20 эпох native. Контроль: 20 эпох native
из исходных COCO-весов. Отдельное предобучение снизило native AP50–95
**0.138 → 0.096**, F1 **0.444 → 0.308**. Дополнительные шаги предобучения не помогли.
Разница ракурсов/размеров рук — возможное объяснение, а не установленная единственная
причина. Поэтому дополнительно проверено совместное обучение вместо переноса этапами:
165 native/Roboflow + 88 MECCANO кадров, 13 эпох, 663 обновления против 660 у контроля.
Фактическое сравнение всех вариантов: `runs/hand_transfer_comparison.json`.

График двух разных задач: [interaction_research_comparison.png](runs/interaction_research_comparison.png).

| Вариант | Native hand AP50 | Native hand AP50–95 | TP / FP / FN при conf=0.25 | F1 |
| --- | ---: | ---: | --- | ---: |
| Native/Roboflow, контроль | 0.469 | **0.138** | 6 / 1 / 14 | **0.444** |
| MECCANO → native | 0.379 | 0.096 | 4 / 2 / 16 | 0.308 |
| Совместный native + MECCANO | 0.226 | 0.075 | 3 / 5 / 17 | 0.214 |

Оба способа добавления MECCANO в этом пилоте ухудшили качество. Среди hand-only
кандидатов выбран контроль; `selected_research.pt` является его копией. Это не
заменяет исходную многоклассовую модель: её кисти на прежней проверке имели более
высокий recall при conf=0.25. AP при разных схемах NMS напрямую не сопоставлялся.

Кандидаты сохраняются в `models/interaction_research/hands/`. Выбор по val является
разработкой модели, а не независимой финальной оценкой. Десять кадров и один seed
недостаточны для устойчивого заключения о переносе на новую банковскую камеру.

## Временная шкала банковского видео

`interaction_timeline.py` строит траектории кистей через сопоставление соседних
наблюдений, измеряет скорость и формирует интервалы `cash_detected`, `hand_near_cash`,
`hand_near_cabinet`, `hand_motion_left/right/up/down`. Сигнал должен присутствовать
минимум в двух последовательных выборках и покрывать ≥0.5 секунды. Пропуск сигнала
разрывает интервал. Пороги движения/близости эвристические, требуют native-проверки.

Необнаруженные деньги получают `unconfirmed`, а не «убраны/спрятаны».
Близость боксов не означает контакт, передачу или пересчёт. Смена track ID возможна
при перекрытии; роли/лица не идентифицируются. Закрытие шкафа и запирание не оцениваются.
Используется v1 ROI, поэтому сохраняется известное ограничение обрезки шкафа.

На исходном `Х-14.mov` обработаны 286 наблюдений. В
`runs/longest_video_interactions/timeline_merl_features.json` добавлены также
64-мерные временные признаки MERL и отдельно помеченные source-domain scores.
Таймкоды признаков проверены на совпадение с детекциями. Эти scores не переименованы
в банковские действия; их перенос не валидирован. Видео входит в native train:
это интеграционная демонстрация, не измерение точности на независимом видео.

Сохранены `timeline_merl_features.features.npz` и
[график наблюдений](runs/longest_video_interactions/timeline.png).
Правила `rules.json` остаются отключёнными; выводы о нарушениях не генерируются.

Ветвь объединения с hand-only предсказаниями отдельно проверена на тех же 286
кадрах: `runs/longest_video_hand_research/predictions.json` и
`runs/longest_video_interactions/timeline_control_hands.json`. Основной график
использует исходный пяти-классовый детектор, а не этот экспериментальный контроль.

## Воспроизведение

Подготовка и обучение на свежих каталогах; существующие экспорты/запуски защищены
от перезаписи. Сетевые операции есть только в загрузчике, обучение и инференс локальные.

```powershell
ML/.venv/Scripts/python.exe -X utf8 ML/fetch_interaction_sources.py --source all
ML/.venv/Scripts/python.exe -X utf8 ML/prepare_interaction_data.py
ML/.venv/Scripts/python.exe -X utf8 ML/run_hand_transfer.py
ML/.venv/Scripts/python.exe -X utf8 ML/run_hand_mixed_probe.py
ML/.venv/Scripts/python.exe -X utf8 ML/train_interaction_temporal.py --out ML/runs/merl_temporal_research_v2 --model-dir ML/models/interaction_research/merl_temporal_v2
ML/.venv/Scripts/python.exe -X utf8 ML/interaction_timeline.py ML/runs/longest_video_objects/predictions.json --output ML/runs/interaction_demo/timeline.json --temporal-weights ML/models/interaction_research/merl_temporal/temporal_best.pt
```

При наличии отдельно проверенных hand-only предсказаний на тех же PTS-кадрах их
можно подключить через `--hand-predictions`. Источник и таймкоды проверяются, деньги
и шкафы сохраняются из исходного детектора. Подавление дубликатов в
`predict_objects.py` теперь можно задать параметром `--nms-iou` (по умолчанию 0.7).

## Условия источников и следующий шаг

[README MERL](https://www.merl.com/pub/tmarks/MERL_Shopping_Dataset/ReadMe.txt)
разрешает исследовательское и образовательное использование.
[EPIC/VISOR](https://epic-kitchens.github.io/VISOR/site) опубликован под CC BY-NC 4.0.
В прочитанных README MECCANO явная лицензия данных не указана; условия коммерческого
применения требуется уточнить у владельца. Это ограничения конкретных источников,
поэтому исследовательские веса сохранены отдельно от основного детектора.
Банковские видео внешним сервисам не отправлялись.

Для обучения именно банковской последовательности нужны проверенные интервалы:
рука тянется/возвращается, деньги видны/перекрыты/неразличимы, пересчёт, передача,
размещение денег, открытие/закрытие хранения. Точка «нарушение на секунде N» не
задаёт эти классы или их границы. Следующий этап — такие native-интервалы, дообучение
временного энкодера с новой банковской головой и проверка на других записях.
Для `cash` по-прежнему нужны дополнительные настоящие банкноты с нашей камеры и
проверенные отрицательные примеры бумаги; эти три источника этого пробела не закрыли.

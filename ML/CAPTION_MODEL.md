## Рабочая интеграция

На Mac `ML_ENGINE=reviewed_pipeline` последовательно запускает замороженную
банковскую голову `bank_only` и базовую Qwen3-VL-4B. После HTTP-загрузки задача
создаётся автоматически. Описания Qwen находятся в `result.observations`, а
подозрительные интервалы — в `result.events`. Запуск API и worker одной командой:
`ML/.venv/bin/python scripts/run_local_pipeline.py` из корня проекта.

В `mlx-vlm==0.4.4` исправлена потеря дополнительных визуальных признаков DeepStack:
`qwen_mlx_compat.py`. Прежние адаптеры v1 обучались до исправления; их загрузка
запрещена. Метрики v1 ниже сохранены как исторические эксперименты, они не
характеризуют текущий исправленный runtime. Рабочая интеграция использует базовые
веса без LoRA; качество описаний не равно 65,8% бинарного классификатора.

## Данные

Из официального **Perception Test** загружены 36 уникальных видео исходного train
раздела: около 404 MiB. Используются интервалы восьми действий с предметами:
открытие, закрытие, помещение внутрь, извлечение, размещение на поверхности,
показ, удержание, подъём и возвращение. Это обычные действия, а не банковские
нарушения. Исходные названия сохранены; обобщённые подписи не добавляют сведения
о конкретном предмете. Аудио не используется.

Материалы: CC BY 4.0, DeepMind Technologies Limited; Viorica Patraucean et al.,
Perception Test, NeurIPS 2023. [Набор и лицензия](https://github.com/google-deepmind/perception_test#license-and-disclaimer).
Из большого ZIP извлекаются только выбранные файлы через проверенные HTTP Range;
контролируются ETag, Content-Range, CRC, длина и SHA-256. Происхождение и точные
интервалы: `external/perception_test/provenance.json` и `manifest.json`.

Всего для caption-эксперимента подготовлены 188 интервалов:

| Источник | Train | Development validation |
| --- | ---: | ---: |
| Подтверждённые пользователем банковские наблюдения | 67 | 14 |
| Оригинальные действия Perception Test | 89 | 18 |

Банковская validation — целиком группа Х-34, Х-35, Х-37, Х-38, Х-39. У Х-38
нет ручных подписей, поэтому в caption-метрике реально четыре исходных видео.
Это **development**, а не финальный независимый тест. Общий ракурс банковской
камеры остаётся прежним. Для внешней validation выделены шесть исходных видео;
после ограничения числа интервалов представлены пять. В train представлены
26 банковских и 24 внешних видео. Между train/validation нет общих SHA и
производных кадров. Не все 36 скачанных внешних видео попали в ограниченный
по числу интервалов эксперимент.

Из 92 ручных наблюдений исключены пять на отложенных Х-16/Х-17, три подписи с
потенциально не визуальными формулировками и три длинных «открывания дверцы».
Исходная ручная разметка не изменена. Пустой или частично размеченный интервал не
становится отрицательным примером. Машинные черновики не используются как истина.

## Обучение

Основа: Qwen3-VL-4B-Instruct, Apache 2.0, локальная MLX-конверсия 4 bit.
SHA базовых весов:
`90eeb02604181dbcccd0a30a1f550a4a8928ca7dcbee4aee1449239306cfdfca`.
Обучаются 327 680 параметров LoRA: q/v проекции последних четырёх языковых
слоёв, rank 8, alpha 1. Визуальный энкодер и базовые веса заморожены.

На интервал используются три хронологических кадра с реальными PTS, размер до
384 px по длинной стороне. Сначала один проход по внешним действиям, затем два
прохода по банковским наблюдениям. AdamW, LR 2e-5, clipping 1, seed 42.
Аугментация: одинаковое изменение яркости трёх кадров в пределах ±10%; временной
порядок, геометрия и мелкие объекты не обрезаются.

Loss считается **только на ответе ассистента** и нормируется на число его токенов,
без изображения и текста вопроса. Есть тесты границы ответа и выравнивания logits.
Пилот: 2,49 с/шаг, пик 5,60 GiB MLX; длительный запуск может быть медленнее.

```bash
ML/.venv/bin/python ML/fetch_perception_actions.py
ML/.venv/bin/python ML/prepare_caption_training.py
ML/.venv-review/bin/python ML/train_caption_lora.py \
  --stage external --steps 89 --eval-every 89 --augment \
  --output ML/runs/caption_lora_external_v1
ML/.venv-review/bin/python ML/train_caption_lora.py \
  --stage bank --steps 134 --eval-every 67 --augment \
  --resume ML/runs/caption_lora_external_v1 \
  --output ML/runs/caption_lora_bank_v1
ML/.venv-review/bin/python ML/evaluate_caption_lora.py \
  --adapter ML/runs/caption_lora_bank_v1
```

`adapter_config.json` содержит происхождение **всех** стадий, SHA адаптера,
выбранный checkpoint и ограничения. Адаптер предыдущей стадии не допускается,
если он видел текущую validation или Х-16/Х-17. Старые банковские головы и
адаптеры в инициализации не участвуют.

## Что измеряется

1. Teacher-forced NLL на человеческих описаниях: соответствие тексту, не
   фактическая точность. После внешней стадии: **3,284 → 2,084** на банковской
   development validation; на внешней **2,952 → 0,349**.
2. Свободная генерация на известных человеческих интервалах: модели видны
   кадры и общий словарь типов, но не правильный тип и не человеческий ответ.
   Сравниваются базовая версия и адаптер. Точное совпадение типа не подтверждает
   каждое слово описания; другое реально видимое действие также может быть
   допустимым ответом при неполной разметке.
3. Полный ролик: валидность результата, число необработанных окон, фактическое
   время, PTS и доказательства. Это проверка работоспособности и покрытия,
   **не** измерение полноты обнаружения всех действий без полной разметки.

После двух банковских проходов NLL на development стал **0,941**; внешний NLL
вырос до **0,689**, что показывает специализацию. В свободной генерации v1
валидный JSON: 13/14 → 14/14; совпадение типа: 5/14 → 6/14.
Для конкретных типов, без `other_visible_action`, результат **2/9 → 2/9**.
Таким образом, существенное улучшение распознавания действий этим обучением
**не доказано**. Автоматической замены модели по одному loss нет.

Следующий исследовательский input-ablation использует те же источники и метки,
но пять кадров до 700 px с контекстом ±0,5 с: `prepare_caption_context.py`.
Он начат после просмотра v1-метрик, поэтому это дополнительная настройка на
development, а не новый независимый тест.

## Полная временная лента

```bash
ML/.venv-review/bin/python ML/dense_observations.py /путь/к/видео.mov \
  --output ML/runs/my_video/report.json
```

По умолчанию используется базовая локальная VLM. Исследовательский адаптер
можно подключить только после переобучения с текущим исправленным runtime;
прежний `caption_lora_bank_v1` намеренно отвергается загрузчиком.

Подключение к кабинету через `ML_ENGINE=dense_vlm` описано в
[инструкции worker](../docs/ML_INTEGRATION.md). Интерфейс умеет показывать описания
и неполное покрытие; существующий режим с YOLO остаётся доступен.

Весь ролик делится на 12-секундные окна, по восемь кадров до 448 px; описания
на русском, до четырёх наблюдений в окне. Каждый результат содержит интервалы,
1–3 JPEG base64 с фактическими PTS и статус машинного предложения. Для доказательств
сохраняется отдельный кадр до 1280 px: у банковских видео — исходное разрешение,
без уменьшения до входных 448 px модели. Рядом создаётся
HTML с локальным видеоплеером, переходами и доказательствами. Внешних сетевых
ресурсов у страницы нет. `--language English` доступен для сравнения.

Шаг выборки около 1,7 с не позволяет гарантировать обнаружение быстрых движений.
Необработанные и невалидные окна помечаются, пустой результат не превращается
в «нарушений нет». Планирование ограничено `--budget-sec` (280 с по умолчанию),
но это не жёсткий таймер GPU и не доказательство пяти минут для HTTP API.
Отдельно сохраняется реальное полное время выполнения.

Х-16/Х-17 блокируются по SHA до извлечения кадров. Их новый анализ в этом этапе
не выполнялся. Видео, кадры, человеческие и машинные описания, логи и веса
хранятся локально в игнорируемых Git каталогах.

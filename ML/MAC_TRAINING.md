## Продолжение с ручной разметкой и отдельным тестом

Импортирован `forte-reviewed-annotations.json` (SHA-256
`ff4ee24bb1a8dba7845a9c7cf8e13d7f6ee0c1de1651a07b0bdb0e90fb989e6a`).
В экспорте 38 задач на 37 уникальных видео, 92 подтверждённых наблюдения.
Проверены происхождение, метки банка, допустимые типы, конечность чисел и границы
интервалов. Описания и видео остаются локально; исходный экспорт сохранён побайтно
в игнорируемой папке `annotations/reviewed/`. Это проверка структуры разметки,
не независимое подтверждение визуальной точности каждого пользовательского описания.

Пустые проверенные задачи Х-22 и Х-38 **не стали отрицательными**. У Х-18, Х-19,
Х-20 нет новых ручных наблюдений; исходные метки/точки банка сохранены.
`other_visible_action` и `visibility_insufficient` не используются как фон или
как подтверждение нарушения. Есть три предупреждения: интервалы открытия дверцы
на Х-30, Х-32, Х-33 длятся 12–18 секунд. Стоит уточнить «открывает» или «уже открыто»;
импорт не меняет вручную выбранный тип. Подробности:
[validation/reviewed_annotation_audit.json](validation/reviewed_annotation_audit.json).

**Для будущего теста зарезервированы Х-16.mov и Х-17.mov**: целиком группа сцен
`green_bag`, один отрицательный и один положительный ролик по исходным меткам банка.
Список контрольных сумм закреплён в
[validation/bank_holdout_v1.json](validation/bank_holdout_v1.json).
Они исключаются из нового обучения, подбора варианта, валидации и аугментаций.
Копия с другим именем определяется по SHA-256. Новые адаптеры инициализируются
заново; старые адаптеры, обученные на всём банке, не используются.
**Это резервирование с текущего этапа:** прежние эксперименты уже использовали
эти записи, поэтому называть их совершенно новым независимым историческим тестом
нельзя. Нового ракурса камеры в этих двух видео также нет.

В development остаётся 38 видео: 20 с событием / 18 без события по метке банка.
Из ручной разметки здесь 87 наблюдений, из них 56 конкретных действий на 27 видео.
Поддержка классов по исходным видео: открытие дверцы 10, закрытие 6, работа с
купюрами 6, купюры на поверхности 3, уход из рабочей зоны 12, передача предмета 2,
предъявление документа 2, перемещение предмета к одежде 2. Перемещение в сумку
подтверждённых примеров не имеет и как обученный класс не выдаётся.

Новый адаптер получает два вида одного момента: стол и полный кадр. Замороженный
R3D18 даёт 512 признаков для каждого вида; адаптер `1024 → 64` обучается заново.
Одна голова ранжирует кандидаты по исходным банковским точкам, другая использует
ручные интервалы для **условного выбора известного действия**. Она не обучается
объявлять все неразмеченные действия отсутствующими. На пересечении интервалов
сохраняются оба известных типа; прилегающие интервалы одного типа объединяются.
Разметка неполная даже внутри отмеченных интервалов: неуказанное действие может
присутствовать. Поэтому относительные оценки классов не являются вероятностями
их наличия, а метрики по отмеченным окнам не измеряют обнаружение во всей записи.

Сравниваются четыре варианта с одинаковыми начальными весами и числом эпох:
только метки банка; банк + аугментации; банк + ручные действия; банк + ручные действия
+ аугментации. Проверка исключает целую группу сцен из обучения. Редкие действия
активируются только при двух исходных train-видео данного класса; отсутствие
класса в отдельном train-разбиении отражается в метриках. Порог событий 0.5 фиксирован.
Выбор кандидатов выполняется по balanced accuracy на development, действий — по
средней точности выбора известного типа на исходное видео. После выбора эти
development-метрики нельзя выдавать за независимую финальную оценку.

```bash
ML/.venv/bin/python ML/import_reviewed_annotations.py \
  "$HOME/Downloads/forte-reviewed-annotations.json" --data "$HOME/Downloads/open"
ML/.venv/bin/python ML/prepare_reviewed_features.py --data "$HOME/Downloads/open" --device mps
ML/.venv/bin/python ML/train_reviewed.py --data "$HOME/Downloads/open"
ML/.venv/bin/python ML/train_reviewed_actions.py --data "$HOME/Downloads/open"
ML/.venv/bin/python -m unittest discover -s ML -p 'test_*training.py' -v
```

Новые артефакты: `runs/mac_reviewed_v1/`. Итоги:
[validation/reviewed_training_summary.json](validation/reviewed_training_summary.json).
В `model_bundle.json` закреплены имена и контрольные суммы двух выбранных голов.
Формат весов — числовой NPZ + JSON, без исполняемого pickle. Действующая модель
в `deployment/` не заменяется автоматически.

Обычный локальный запуск:

```bash
ML/.venv/bin/python ML/predict_reviewed.py /путь/к/видео.mov \
  --output ML/runs/reviewed_prediction.json --device mps
```

Для **будущего**, явно начатого теста (в ходе обучения эти команды не выполняются):

```bash
ML/.venv/bin/python ML/predict_reviewed.py "$HOME/Downloads/open/videos/Х-16.mov" \
  --allow-reserved-test --output ML/runs/test_16.json --device mps
ML/.venv/bin/python ML/predict_reviewed.py "$HOME/Downloads/open/videos/Х-17.mov" \
  --allow-reserved-test --output ML/runs/test_17.json --device mps
```

Без `--allow-reserved-test` новый CLI отказывается анализировать эти видео.
Рядом с каждым JSON создаётся локальная HTML-страница с видеоплеером, шкалой записи,
переходами к эпизодам, контекстом до/после и подсказками типов. Она не использует
внешние библиотеки, сетевые запросы или загрузку видео на сервер.
При явном запуске сохраняется журнал `.test-use.json`. После просмотра результатов
нельзя подстраивать модель под эти записи и продолжать называть их независимым тестом.
Ответ включает интервалы-кандидаты, таймкоды и `action_suggestions`; поля `type`
и `rule_id` остаются `null`, `requires_review=true`. Факт предъявления документа,
передачи предмета или открытия шкафа сам по себе не доказывает нарушение.

Для кандидатов выбран `bank_only.npz`: precision 0.652, recall 0.750. Постоянный

Общий адаптер показал слабое распознавание действий, поэтому выполнен дополнительный
**исследовательский** прогон: отдельный регуляризованный линейный классификатор

нормализация также обучается только внутри train каждого разбиения. Линейные
логиты точно экспортированы в существующий ReLU-формат через пары положительных

## Что именно обучено

Замороженный [R3D18 Kinetics400](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.video.r3d_18.html)
извлекает 512 признаков из 16 кадров при 4 FPS. На Mac используется Metal/MPS.
Контекст симметричен относительно таймкода: это анализ записи, а не предсказание
будущего действия. Вход 112×112 ограничивает видимость мелких денег и документов.
Для банковских видео применяется область `[0, 300, 464, 661]` без изменения пропорций.
Она относится к исходной камере 464×848; перенос на другой ракурс не проверен.

1. Контроль: взвешенная логистическая регрессия по банковским точкам.
2. Адаптер `512 → 64 → 1`: сначала MIL-обучение на внешних видео, затем дообучение
   по банковским точкам. MIL использует верхние 20% окон видео и не назначает
   положительную метку каждому кадру. Сам видеобэкбон не размораживается.
3. Такой же адаптер со случайной инициализацией — контроль пользы внешнего обучения.
4. Два дополнительных варианта с мягкими аугментациями на банковском этапе.

Аугментации: яркость 0.88–1.12, контраст и gamma 0.92–1.08, слабое размытие,
скорость контекста 0.9–1.1. Один фотометрический набор применяется ко всем кадрам
ролика. Рабочая область и центральный таймкод сохраняются. Аугментированные окна
берутся только из train текущего разбиения; оценка всегда идёт по оригиналам.
Число эпох, шагов и суммарный вес исходного видео одинаковы в сравниваемых вариантах.

## Результаты

Машиночитаемый итог, окружение и результаты всех вариантов:
[validation/mac_training_summary.json](validation/mac_training_summary.json).
Пройдены 10 тестов, проверен офлайн-инференс сохранённого адаптера на MPS.

Основная диагностическая проверка — исключение целой группы похожих сцен
(`LeaveOneGroupOut`), 40 видео. Порог 0.5 фиксирован; score не откалиброван.

| Вариант | Найдено из 21 | Ложных тревог из 19 | F1 | Найдено и таймкод ±2 с |
| --- | ---: | ---: | ---: | ---: |
| R3D18 + линейный классификатор | 16 | 13 | 0.640 | 9 |
| Адаптер, только банк | 15 | 13 | 0.612 | 7 |
| Адаптер, банк + аугментации | 16 | 12 | 0.653 | 8 |
| Внешнее предобучение → банк | 19 | 18 | 0.655 | 7 |
| Внешнее предобучение → банк + аугментации | 19 | 18 | 0.655 | 7 |

Внешнее предобучение увеличило число обнаружений вместе с ложными тревогами.
На переносе между группами условий съёмки pink→white F1 снизился с 0.600 у контроля
до 0.462; с аугментациями внешнего варианта — 0.500. У контроля аугментации дали
0.444 на этом переносе. Устойчивое преимущество не установлено.

На внешней отложенной выборке из 36 видео F1 = 0.824, precision = 0.933,
recall = 0.737. Эта проверка не разделяет актёров/сцены и не измеряет качество
банковских событий. Высокую внешнюю метрику нельзя переносить на банк.

Для масштаба: постоянный ответ «есть событие» на банковских данных имеет F1 = 0.689
при 19 ложных тревогах. Одного F1 недостаточно, чтобы объявлять новые модели хорошими.
Проверки используют уже изученный исторический набор одной камеры; независимого
финального теста здесь нет. Все варианты сохранены, автоматического выбора или
подмены основной модели нет.

Дополнительно проверено усиление штрафа за 20% самых сложных окон корректных
train-видео (`--hard-negatives`, `runs/mac_hard_negative/`). У контроля без внешнего
предобучения ложные тревоги снизились с 13 до 10, но найденных событий стало 12
вместо 15. Внешний адаптер почти перестал выдавать события. Этот вариант не принят.
Это дополнительный исследовательский прогон после изучения ошибок, не новый
независимый тест.

```bash
  --with-augmentation --output ML/runs/mac_transfer_augmented
ML/.venv/bin/python -m unittest discover -s ML -p 'test_t*.py' -v
```

На этой машине `.venv` создан с `--system-site-packages` для использования уже
установленных Torch 2.11.0 / Torchvision 0.26.0. Команды выше создают отдельную
установку с явными зависимостями. Веса R3D18 проверяются по полной SHA-256.
Сеть нужна для первоначальных скачиваний, не для анализа видео.

`runs/mac_temporal/` содержит линейную голову, предсказания и метрики.
`runs/mac_transfer_augmented/` содержит четыре адаптера `*_head.npz`, метрики,
предсказания на исключённых видео и протокол. NPZ содержит массивы и JSON,
инференс не десериализует исполняемый pickle.

```bash
ML/.venv/bin/python ML/predict_temporal.py /путь/к/видео.mov \
  --head ML/runs/mac_transfer_augmented/random_init_augmented_head.npz \
  --output ML/runs/candidates.json --device mps
```

Ответ содержит `requires_review`, `automatic_violation_detection=false`, события
с `type=null`, `rule_id=null` и признак `source_seen_during_training`. Результат
на видео, участвовавшем в финальном обучении, не является проверкой качества.
Это исследовательский CLI, не замена API для жюри.

Roboflow скачивается отдельно через `fetch_roboflow.py`, ключ читается из локального
`ML/.env`. Аудит воспроизводится командой `ML/.venv/bin/python ML/audit_roboflow.py`.
Ключи, сырые данные, кадры, кэши и большие веса исключены из Git.

## Уточнение разметки

Создана очередь из 41 фрагмента: все банковские точки и пики модели на отложенных
отрицательных видео. Исходная метка банка хранится отдельно от наблюдаемых действий.
Получены предложения для всех 41 фрагмента; проверены JSON-схема и допустимость
ссылок на кадры. Это проверка структуры ответов, а не точности описанных действий.
На этом первом этапе подтверждённых человеком новых классов ещё не было.
Последующий ручной экспорт и его использование описаны в начале документа.
Предварительный разбор выполняется **локально** Qwen3-VL-4B-Instruct, 4-bit MLX.
[Исходная модель](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct) имеет Apache 2.0;
[MLX-конверсия](https://huggingface.co/mlx-community/Qwen3-VL-4B-Instruct-4bit)
закреплена по revision и SHA-256. Для неё используется отдельное окружение.

```bash
python3 -m venv ML/.venv-review
ML/.venv-review/bin/python -m pip install -r ML/requirements-review-mac.txt
ML/.venv-review/bin/python ML/download_review_model.py
ML/.venv/bin/python ML/prepare_local_review.py --data "$HOME/Downloads/open"
ML/.venv-review/bin/python ML/review_with_local_vlm.py
ML/.venv/bin/python ML/build_review_page.py
open ML/annotations/local_review/index.html
```

Локальная страница показывает исходное видео, кадры, предложения и форму проверки
интервалов/типов. Экспорт включает только фрагменты, явно отмеченные пользователем
как проверенные. Машинные предложения имеют `allowed_for_training=false` и не
участвуют в выполненных экспериментах. Пять кадров вокруг точки не заменяют
просмотр всей операции. Юридическая квалификация и ссылки на правила не генерируются
визуальной моделью; ограничения источников остаются в [CRITERIA.md](CRITERIA.md).

Следующий набор подтверждённой разметки должен различать наблюдаемые действия,
их интервалы, видимость предметов и контекст операции. Дрожание рук, эмоции и
предполагаемое намерение украсть не являются целевыми классами.

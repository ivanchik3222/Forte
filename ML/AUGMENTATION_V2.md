# Аугментации v2: отзеркаливание, grayscale, scale и FPS

Подготовлены новые данные и отдельные запуски на RTX 4050. MERL/EPIC/MECCANO остаются
в отменённом архиве и не используются. Основная модель `models/cash_detector/best.pt`
сохранена; новые кандидаты записываются в отдельные каталоги.

## Данные для детектора

`datasets/cash_objects_aug_v2`: **511 изображений, 1753 бокса**.
Train **495**, val **10**, test **6**. Это 45 исходных train-изображений и 450
производных вариантов. Источники исходного train сохранены: 25 банковских кадров,
8 Roboflow, 12 Open Images. Новых независимых сцен от аугментации не появилось.

Варианты каждого train-изображения:

| Преобразование | Параметры / обработка боксов |
| --- | --- |
| Horizontal mirror | Перестановка пикселей и x-координат боксов |
| Grayscale | Три одинаковых канала RGB; геометрия сохранена |
| Mirror + grayscale | Совместное преобразование пикселей и боксов |
| Scale down | 0.88–0.95, фиксированный размер холста, свободное поле 114 |
| Scale up | Запрос 1.05–1.15, сдвиг сохраняет кисти/деньги/сумки/шкафы |
| Dark / bright | Мягкие gain/gamma и слабый шум, как в v1 |
| Rotation | ±1–3°, расширенный холст, все четыре угла бокса пересчитаны |
| Motion blur | Ядро 3 пикселя, горизонтальное или вертикальное |
| JPEG | Перекодирование quality 70–90 |

Scaling меняет **размер объектов относительно фиксированного холста**. Обычное
изменение размера всего изображения могло бы отмениться при последующем resize
YOLO. Положительные объекты не удаляются. При увеличении допускается частичная
обрезка person с сохранением не менее 65% преобразованного бокса; прочие классы
полностью сохраняются. Для восьми изображений увеличение без потери целевых
объектов оказалось невозможным — применено уменьшение, это отмечено в manifest.

Для каждой производной сохранены родитель, SHA-256 родительского изображения,
source/scene group, affine matrix и параметры. Преобразованы также координаты
ранее замаскированных неоднозначных участков. Боксы получены из существующей
визуально проверенной разметки; экспертной приёмки новых сцен не добавлено.
Val/test JPEG и YOLO labels **побайтно совпадают** с `cash_objects_v1`.
Контактные таблицы находятся в `datasets/cash_objects_aug_v2/previews/`.

## Видеоварианты с разными FPS

`datasets/cash_video_aug_v2`: **150 шестисекундных MP4, 7500 кадров**,
25 исходных anchor-кадров из **24 уникальных train-видео**. Шесть вариантов:

- original 2 FPS;
- original 12 FPS;
- mirror 12 FPS;
- grayscale 6 FPS;
- scale down 6 FPS;
- scale up 12 FPS.

Клипы берутся вокруг существующего размеченного момента или выбранного ранее
среднего кадра нормального видео. Геометрия и параметры постоянны внутри клипа;
случайный scale/цвет не меняется от кадра к кадру. ROI соответствует исходной
разметке `[0,300,464,610]`. Сохраняется известное ограничение обрезки шкафов v1.

Изменение FPS выполняется выборкой ближайших исходных кадров с записью
output PTS → original PTS. **Скорость события и его время не меняются**; это
ресэмплинг, а не ускорение/замедление. Ни одно val/test-видео не аугментировалось.

У клипов только исходные слабые бинарные метки видео/точек. Плотных боксов на
произвольных кадрах и интервалов банковских действий нет. Поэтому кадры MP4
не объявляются новой истинной разметкой YOLO. Детектор обучается на проверенных
покадровых преобразованиях, а видеоклипы участвуют в отдельном бинарном пилоте.

## Обучение YOLO и сравнение

Одинаковые YOLO11n COCO-веса, seed 42, вход 640, batch 5, AdamW, lr=0.0005,
freeze=10, AMP выключен. Дополнительные онлайн-аугментации выключены;
Albumentations в окружении не установлен.

| Запуск | Train | Эпох | Шагов оптимизатора |
| --- | ---: | ---: | ---: |
| Прежние v1 аугментации, новый контроль | 225 | 44 | 1980 |
| Новые v2 аугментации | 495 | 20 | 1980 |

Выбор checkpoint по val. Окончательная проверка обоих best на исходных десяти
val-кадрах через `evaluate_detector.py`, NMS IoU 0.7. Дополнительно TP/FP/FN
при conf=0.25 и IoU сопоставления ≥0.5. Test v1 повторно не оценивается:
он уже использован для диагностики предыдущих изменений.

Метрики, поклассовые AP и counts: `runs/cash_aug_v2_comparison.json`.
Кандидат, обученный именно на v2: `models/cash_detector_aug_v2/best.pt`, `last.pt`,
`training_args.yaml`, `model_card.json`, `DATA_ATTRIBUTION.md`.
Все эпохи/промежуточные веса и логи — `runs/cash_aug_v2_control*` и
`runs/cash_aug_v2_expanded*`. Частота val и шаг изменения learning rate по эпохам
различаются; это сравнение с равным числом обновлений, одним seed и маленьким val.
Оно не измеряет отдельно пользу каждого из десяти преобразований.

Проверка сохранённых best на исходном val:

| Вариант | mAP50 | mAP50–95 | Precision / recall при conf=0.25 | TP / FP / FN | Micro F1 |
| --- | ---: | ---: | --- | --- | ---: |
| Новый контроль с прежними аугментациями | 0.599 | 0.264 | 0.708 / 0.642 | 34 / 14 / 19 | 0.673 |
| Полный пакет v2 | 0.518 | **0.276** | 0.824 / 0.528 | 28 / 6 / 25 | 0.644 |

Прибавка mAP50–95 **0.01149**, или 1.15 процентного пункта, сопровождается
снижением recall при рабочем пороге. AP50–95 кистей 0.136 → 0.164, денег
0.144 → 0.190, однако при conf=0.25 число найденных кистей 10 → 6 из 20,
денег 1 → 0 из 3. Таким образом, пакет нельзя объявить общим улучшением.

Дополнительная сетка operating point на val (confidence 0.05/0.10/0.15/0.25/0.35/0.50,
NMS 0.3/0.5/0.7, вход 640/960) дала лучший micro F1 0.674 при 640, NMS 0.3,
conf=0.15; деньги при этом ещё пропущены. При conf=0.10 и NMS 0.3 появляется
1/3 cash, общий F1 0.667. Это подбор на val, а не независимый прирост.
Артефакты: `runs/detector_diagnosis_aug_v2/`. Исходный основной детектор имел
F1 0.716 при conf=0.25 в прежней проверке и остаётся рабочим.

## Мягкий пакет для мелких объектов

После снижения recall проверен follow-up без motion blur, JPEG-перекодирования,
уменьшения и дополнительной mirror-grayscale копии. Пять вариантов: mirror,
grayscale, safe scale up, dark, bright. Гипотеза: мелкие деньги могут терять детали
при слишком сильной деградации; этот пилот не устанавливает причину предыдущего
снижения и не изолирует эффект одного преобразования.

`datasets/cash_objects_aug_focused_v2`: 270 train, 10 val, 6 test, 993 бокса.
Общие изображения и labels побайтно совпадают с полным v2. Train YOLO11n с теми же
параметрами: 37 эпох, 1998 шагов, на **0.91% больше**, чем 1980 у контроля/полного
пакета. Val частота также отличается. Веса сохраняются в
`models/cash_detector_aug_focused_v2/`, отчёт — `runs/cash_aug_v2_focused_comparison.json`.
Малый val и адаптивный выбор нового опыта требуют отдельного финального holdout.

Мягкий пакет дал mAP50–95 **0.241**, precision **0.750**, recall **0.623**,
F1 **0.680**, TP/FP/FN **33/11/20**. При conf=0.25 найдены 9/20 кистей и 1/3 cash.
Он не превзошёл текущую основную модель по фиксированному F1 0.716. Полный пакет
выиграл по общему mAP, но проиграл по recall и F1 при рабочем пороге. Поэтому
основная модель сохранена; новые варианты доступны как кандидаты для исследования.

Общая сводка: `runs/augmentation_v2_summary.json`.
[График обучения, поклассовых AP и рабочих метрик](runs/augmentation_v2_comparison.png).
Основная v1 модель обучалась за 900 шагов; её строка в сводке — эксплуатационный
ориентир. Вывод о эффекте полного пакета относится к контролю 1980 шагов.

## Отдельное обучение на видеоклипах

`train_native_video_aug.py` использует все кадры клипов при их реальных 2/6/12 FPS.
Энкодер ImageNet ResNet18 заморожен. Для шестисекундного окна берутся mean/std/max
512-мерных признаков и средняя абсолютная скорость изменения признаков **в секунду**,
всего 2048 величин. Это признаки для бинарной головы, не измерение физических рук.

Обучается StandardScaler + LogisticRegression C=0.01. Каждый из 24 уникальных
исходных роликов имеет одинаковый суммарный вес независимо от количества копий
и двух anchor-точек дубля. Суммарный sample_weight одинаков у контроля и нового
варианта; стандартизация рассчитывается с теми же train-весами.

Контроль — 25 original_12fps клипов. Новый вариант — все 150 клипов. Оценка на
**полных исходных десяти val-видео**, выборка 2 FPS и сканирование окон ±3 секунды.
Истинные положительные таймкоды не выбирают окна при оценке. Video score — максимум
по всем окнам, порог заранее фиксирован 0.5.

| Видеоклассификатор | Precision | Recall | F1 | TP / FP / FN |
| --- | ---: | ---: | ---: | --- |
| Контроль | 0.556 | 1.000 | **0.714** | 5 / 4 / 0 |
| Аугментированные клипы | 0.500 | 1.000 | 0.667 | 5 / 5 / 0 |

Аугментации не улучшили этот слабый бинарный пилот. Большое число ложных тревог
показывает, что такой score пока не подходит для обнаружения нарушений. Длинные
записи дают больше окон и могут усиливать проблему максимума. Типы действий и
проверенные правила не обучались. Object AP детектора и F1 бинарной головы —
разные задачи и разные единицы наблюдения.

Эти значения не сравниваются напрямую с прежним OOF F1 бинарного baseline:
в нём были другие признаки, обучение и разбиение сорока видео, здесь только десять val.

Веса: `models/native_video_aug_v2/control.joblib`, `augmented.joblib`,
`model_card.json`. Метрики и предсказания: `runs/native_video_aug_v2/`.
Отдельный прогон `Х-14.mov` — проверка загрузки/инференса на train-источнике,
а не независимая оценка. Основной бинарный baseline и основной детектор не заменены.

Запуски защищены от перезаписи. Команды экспорта/обучения ниже рассчитаны на
свежие соответствующие каталоги; для нового опыта задавать новые output/prefix.

```powershell
ML/.venv/Scripts/python.exe -X utf8 ML/augment_detection_v2.py
ML/.venv/Scripts/python.exe -X utf8 ML/augment_native_videos_v2.py
ML/.venv/Scripts/python.exe -X utf8 ML/run_augmentation_v2.py
ML/.venv/Scripts/python.exe -X utf8 ML/run_focused_augmentation_v2.py
ML/.venv/Scripts/python.exe -X utf8 ML/train_native_video_aug.py
ML/.venv/Scripts/python.exe -X utf8 ML/report_augmentation_v2.py
ML/.venv/Scripts/python.exe -X utf8 -m unittest discover -s ML -p 'test_*.py'
```

```powershell
ML/.venv/Scripts/python.exe -X utf8 ML/predict_objects.py ML/open/open/videos/Х-14.mov --weights ML/models/cash_detector_aug_v2/best.pt --output ML/runs/longest_video_objects_aug_v2 --roi 0 300 464 610 --fps 2
ML/.venv/Scripts/python.exe -X utf8 ML/predict_native_video_aug.py ML/open/open/videos/Х-14.mov --model ML/models/native_video_aug_v2/augmented.joblib --output ML/runs/native_video_aug_v2/longest_video_prediction.json
```

## Проверки и практические пределы

Проверяются grayscale/RGB, зеркало и боксы, реальное изменение масштаба, сохранение
целевых объектов, точные копии holdout, отсутствие source leakage, реальные FPS
кодированных MP4, сохранение времени событий и нормализация скорости по времени.
Также проверен одинаковый суммарный вес исходного видео при разном числе вариантов.

Аугментации не устраняют обрезку шкафа и не добавляют независимых банкнот/сумок.
В native train по-прежнему 13 боксов денег и одна сумка; в val всего 3 и 2.
Прибавка общего mAP не гарантирует роста recall денег при рабочем пороге.
Следующие изменения требуют реальных кадров, исправления ROI и интервальной
разметки действий, затем независимой проверки на других записях.

Методические источники: [Ultralytics augmentation](https://docs.ultralytics.com/guides/yolo-data-augmentation/)
для зеркала, масштаба, цветовых и мягких геометрических преобразований;
[Torchvision RandomGrayscale](https://docs.pytorch.org/vision/stable/generated/torchvision.transforms.v2.RandomGrayscale.html)
для grayscale с сохранением числа каналов. Конкретные ограничения боксов и
параметры выбраны для мелких объектов этого проекта.

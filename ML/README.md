# Локальный ML прототип для анализа кассовых видео

**Apple Silicon / локальный запуск 17.10.2026:** [ручная разметка, новый этап обучения,
резерв Х-16/Х-17 для теста и локальный просмотр результатов](MAC_TRAINING.md).
Внешние данные, аугментации и предыдущие эксперименты описаны там же. Это отдельные исследовательские
кандидаты; действующий `deployment/cash_detector.pt` не заменён. Ниже описана
история предыдущих экспериментов на Windows/RTX 4050.

Проверка требований жюри и вопросов/ответов из кейса:
[CASE_QA_AUDIT.md](CASE_QA_AUDIT.md). В ней отдельно отмечены неподтверждённые
нормативные основания и несовпадение текущего API с контрактом жюри.

Модель подключена к актуальным backend/frontend: загрузить видео → открыть запись → «Наблюдения модели» → запустить анализ. Рабочие веса поставляются в `deployment/cash_detector.pt`. [Запуск, очередь и API](../docs/ML_INTEGRATION.md). [Прогон всех исходных видео](OPEN_VALIDATION.md).

Реализованы проверка разметки, объединение дубликатов, бинарный baseline, предложения боксов Grounding DINO и обучение детектора YOLO11n на исправленной разметке с аугментациями. Детектор обучен на RTX 4050, выбран по val и проверен на test; веса — `models/cash_detector/best.pt`. Метрики и ограничения: [RESULTS.md](RESULTS.md). Это исследовательский прототип: он пока не выдаёт подтверждённые типы нарушений и нормативные заключения.

## Запуск из корня репозитория

```powershell
python -m venv ML/.venv
ML/.venv/Scripts/python.exe -m pip install --upgrade pip
ML/.venv/Scripts/python.exe -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
ML/.venv/Scripts/python.exe -m pip install -r ML/requirements.txt
ML/.venv/Scripts/python.exe ML/download_models.py --resnet --grounding-dino
ML/.venv/Scripts/python.exe ML/prepare_review.py
ML/.venv/Scripts/python.exe ML/pipeline.py
ML/.venv/Scripts/python.exe ML/annotate_objects.py --limit 6
ML/.venv/Scripts/python.exe -m unittest discover -s ML -p test_pipeline.py
ML/.venv/Scripts/python.exe ML/predict.py "ML/open/open/videos/Х-1.mov"
```

В текущем рабочем окружении `.venv` создан с `--system-site-packages`. Теперь CUDA-сборки PyTorch 2.6.0 и Torchvision 0.21.0 установлены непосредственно в `ML/.venv`; системные CPU-сборки они не изменяют. Часть остальных зависимостей наследуется из системного Python, поэтому полной изоляции нет. Команды выше предназначены для новой изолированной установки; текущие версии и проверка CUDA фиксируются в `environment.json`. Исходное CPU-окружение baseline сохранено в `runs/baseline/environment_original.json`.

Первый бинарный baseline выполнен на CPU. Для обучения детектора используется RTX 4050, CUDA 12.4. Проверены матричное умножение и NMS на GPU. Команды установки выше рассчитаны на эту GPU-машину; для CPU-окружения заменить `cu124` на `cpu`. Большая VLM для этих экспериментов не требуется.

После загрузки весов `pipeline.py`, `predict.py` и `annotate_objects.py` работают с локальными файлами. Загрузка моделей, внешних датасетов и установка зависимостей требуют сети. Кадры, видео и описания ForteBank не передаются в AI API.

## Метод

ResNet18 ImageNet1K V1 используется как замороженный энкодер. Для каждого выбранного кадра вычисляются признаки общего плана и верхней области сцены. Выборка — 2 FPS. В окне ±2 секунды агрегируются среднее, стандартное отклонение, максимум и изменение признаков между кадрами. Обучается `StandardScaler + LogisticRegression`, C=0.01.

Положительные обучающие окна центрируются на исходных отметках с небольшим смещением. Отрицательные берутся только из исходных видео «без нарушения». Неотмеченные части положительных видео не считаются корректными. Вес каждого исходного видео нормируется; классы балансируются по суммарному весу.

Дубликаты объединяются по SHA-256 до разбиения; у Х-4/Х-47 сохраняются обе точки. Используется пятикратная проверка по уникальным видео и отдельный перенос pink→white по видимым условиям съёмки/одежде, без распознавания личности. Первая проверка разделяет копии, но не исключает похожие сценарии и общий фон, поэтому не оценивает перенос на новую камеру.

Порог 0.5 фиксирован заранее. Вердикт видео получается из максимального оконного score. Это может увеличивать число ложных срабатываний на длинных роликах. Score не является откалиброванной вероятностью нарушения. Одна максимальная точка не заменяет полноценную локализацию нескольких событий.

## Файлы результатов

- `runs/baseline/metrics.json`: метрики, параметры и ограничения.
- `runs/baseline/oof_predictions.json`: предсказания на отложенных видео, не на обучающих окнах.
- `runs/baseline/appearance_holdout_predictions.json`: перенос между группами съёмки.
- `runs/baseline/classifier.pkl`: финальный классификатор на всех уникальных видео. Загружать только доверенные локальные pickle.
- `annotations/review_queue.csv`: предварительная классификация наблюдаемых действий, поля подтверждения типов и правил.
- `annotations/proposals/grounding_dino.json`: непроверенные предложения боксов.
- `CRITERIA.md`, `rules.json`: нормативные источники, наблюдаемые условия и исключения.

Предложения Grounding DINO — `unreviewed`, не истинная разметка. Модель ищет людей, руки, сумки, банкноты, шкафы/сейфы, двери, телефоны и чашки. Наличие предмета само по себе не является нарушением. Нужна ручная проверка ошибок, особенно на мелких банкнотах и руках.

Текущая обрезка — эвристика под исходные видео; при новом ракурсе нужна локализация рабочей зоны. В бинарном `predict.py` таймкоды берутся из позиции декодера OpenCV. Новый `predict_objects.py` использует PTS PyAV относительно начала видео и возвращает боксы в координатах исходного кадра.

## Следующий этап

Исправленные боксы экспортированы в `datasets/cash_objects_v1/`: 61 изображение, 233 объекта, YOLO и COCO. Классы: `person`, `hand`, `cash`, `bag`, `storage_cabinet`. Внешние изображения используются только в train. Разметка прошла визуальный просмотр Codex, экспертного подтверждения пока нет. После аугментаций train расширен до 225 изображений, детектор обучен и сохранён.

Для повторного экспорта уже исправленной локальной разметки и проверки загрузки:

```powershell
ML/.venv/Scripts/python.exe ML/build_detection_dataset.py
ML/.venv/Scripts/python.exe -m unittest discover -s ML -p 'test_*.py'
```

Для Torchvision готов загрузчик `CashDetectionDataset` в `detection_data.py`; для YOLO — `datasets/cash_objects_v1/data.yaml`. Порядок классов и ограничения разметки описаны в [DATASET.md](DATASET.md). После переноса проекта пересобрать экспорт: YAML содержит абсолютный путь.

Обучение детектора при наличии исправленной локальной разметки:

```powershell
ML/.venv/Scripts/python.exe -m pip install -r ML/requirements-detector.txt
ML/.venv/Scripts/python.exe ML/augment_detection_dataset.py
ML/.venv/Scripts/python.exe -m unittest discover -s ML -p 'test_*.py'
ML/.venv/Scripts/python.exe ML/run_detector_experiment.py --device 0 --lr 0.0005 --freeze 10
```

Аугментации расширяют train до 225 изображений, val/test остаются исходными. Скрипт сравнивает аугментированный и контрольный запуски, выбирает веса по val и оценивает выбранные веса на test. Сохраняются `models/cash_detector/best.pt`, `last.pt`, параметры и метрики. Подробности: [AUGMENTATION.md](AUGMENTATION.md).

Далее расширить реальные примеры мелких предметов и частично видимых шкафов, проверить разметку экспертно и оценивать следующие изменения на новом независимом holdout. Подтвердить типы событий и интервалы в очереди разметки. Затем использовать траектории людей, рук и предметов и временные правила, сравнивая с сохранённым baseline. Наличие объекта не является меткой нарушения. До этого не подключать экспериментальный бинарный score как готовое юридическое решение к API жюри.

Веса ResNet18 взяты из [официальной поставки Torchvision](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html). Grounding DINO Tiny — [официальная карточка IDEA Research](https://huggingface.co/IDEA-Research/grounding-dino-tiny), Apache-2.0. Для коммерческого выпуска отдельно зафиксировать условия выбранных весов и обучающих данных; лицензия библиотеки не заменяет такую проверку.

## Руки и последовательности действий

Рабочая модель — `models/cash_detector/best.pt`. Временная шкала строится по её
детекциям и траекториям кистей; дополнительные модели действий не загружаются.

```powershell
ML/.venv/Scripts/python.exe -X utf8 ML/interaction_timeline.py ML/runs/longest_video_objects/predictions.json --output ML/runs/longest_video_interactions/timeline.json
```

Это наблюдения движения и близости предметов. Пропущенные деньги получают статус
`unconfirmed`; распознавание пересчёта, передачи денег и нарушений требует отдельной
разметки действий. Три теста временной обработки проверяют пропуски и сопровождение.
Пилоты MERL/EPIC/MECCANO отменены и изолированы: [статус](EXTERNAL_INTERACTIONS.md).
Следующая итерация на банковских кадрах: [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md).
